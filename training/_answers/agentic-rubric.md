## Reference points a good M3 solution hits

1. **Cache (`apps/api/src/lib/cache.js`).** Wrap `storeGet`/`storeSet`/`storeDel` so a Redis error or a timeout (for example 50–100 ms via a `Promise.race` or ioredis `commandTimeout`) degrades to a miss, then call the loader (Postgres). Set `enableOfflineQueue: false` so a disconnected client fails fast instead of queueing. `invalidate` failures must be logged and counted. A missed invalidation now means a stale authorization decision for up to `MEMBERS_TTL` (60 s), so either retry the delete or shorten the TTL while Redis is unhealthy. Say which one you chose.
2. **Enqueue.** The request must not fail after the commit because Redis failed. The robust answer is a transactional outbox (curriculum 01): write an `OutboxEvent` row in the same `$transaction` as the change (`issue.service.js` update transaction, `comment.service.js:35`), and let a relay in the worker move rows to BullMQ or process them directly. The cheaper answer is to catch the enqueue error, log and count it, and return success, accepting lost notifications. That's acceptable only if the explanation says so and adds an alert.
3. **Event identity.** Whatever path delivers the job, its `eventId` must be stable per domain event (for example the outbox row id or the `ActivityEvent.id`), not per enqueue attempt, so `handleNotificationJob`'s `dedupeKey` (`notification-handler.js:42`) dedupes redelivery correctly. See curriculum 02.
4. **BullMQ connection.** `apps/api/src/jobs/queue.js` passes a bare `{host, port}`. The producer side should fail fast (`enableOfflineQueue: false`); the worker side should keep `maxRetriesPerRequest: null` (BullMQ requires it for blocking commands).
5. **Tests.** At least one test with `__NO_ROLLBACK__` and a cache/queue that throws or times out (a fake store, or a real Redis on a closed port). It asserts: the list endpoint returns 200 within budget, the assignment is committed, and the notification is either in the outbox or the failure is counted.
6. **Docs.** Fix `docs/RUNBOOK.md` "Queue backlog" to describe the real behaviour. Add the new metric names.
